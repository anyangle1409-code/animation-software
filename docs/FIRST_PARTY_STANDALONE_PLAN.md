# First-party standalone roadmap

## Status of this document

This is the durable high-level roadmap. It is **not** the operational handoff.

For current branch, exact next task and latest verified state, use `docs/CURRENT_HANDOFF.md`.

## Required product target

Produce a distributable Home Gym PT product whose shipped runtime and shipped creative assets are project-authored and self-contained.

The required Level-1 target is:

- zero third-party runtime implementation in the shipped product;
- zero legacy/imported/MakeHuman-derived production character content;
- zero third-party models, textures, fonts, audio or other bundled creative assets;
- zero remote CDN/script/font/runtime resource dependency;
- project-authored exercise/generation/validation data and production assets.

External development tools may remain development-only. Blender, Git/GitHub, Python, Node/npm, TypeScript/Vite/Vitest/Playwright and GPT/Claude do not violate Level 1 merely by being used to build/test the product.

A later Level-2 goal could also replace third-party build/test tooling, but that is optional and must not distract from Level 1.

## Frozen provenance decisions

- V15f is complete as a **legacy/reference benchmark only**.
- The imported/high-detail V5-V15f/CORNER_FINAL lineage is not eligible as the final production character.
- MakeHuman-derived built-in anatomical body data is not eligible for the final first-party production path.
- ORIGINAL v1 is the clean-room production character line.
- `hgpt_canonical_v4_original` is the independent 63-bone production rig target.
- No legacy geometry, topology, UVs, weights, materials, morphs, bind matrices or imported-character-derived rest transforms may be transferred into ORIGINAL v1.

See `docs/DECISION_LOG.md` and `docs/AI_OPERATING_CONTRACT.md` for the binding rules.

## Current workstreams

### A. First-party runtime

Direct Zustand has already been replaced by the project-owned store.

Grid, Orbit and Transform behaviour have project-owned implementations. The remaining migration proceeds in controlled parity-gated stages:

1. complete R3F consumer/host migration;
2. remove R3F when live parity is demonstrated;
3. replace React/ReactDOM UI/lifecycle;
4. replace Three.js math/scene/GLB/renderer responsibilities last;
5. run production-output, network, dependency and offline/release gates after every removal.

Drei currently has zero source imports but its package removal is held by the separate physical desktop/iPhone parity gate.

The exact live dependency/import surface is generated by the audit tools; do not copy historical counts into planning decisions.

### B. ORIGINAL v1 character

O1 established a clean first-party scaffold and provenance proof. It is not a finished production model.

Current character work proceeds through O2 and later stages using the independent v4 target:

1. materialise `hgpt_canonical_v4_original` in the clean-room Blend;
2. author neutral anatomy independently;
3. establish deformation-friendly topology and original garment/material work;
4. bind/weight to the production rig;
5. run joint-range, contact, grip, push-up, curl, press, pull-up, squat/lunge and whole-body movement-envelope gates;
6. complete final visual/deformation acceptance.

Do not tune exercise mechanics to hide character defects.

## Reference policy

Allowed production inputs include project-authored numerical specifications, project-owned rig semantics/algorithms, generic anatomical/biomechanical knowledge and independently authored ORIGINAL geometry/materials.

Legacy assets may be used only for an explicitly authorised abstract comparison or failure example. They are never a production geometry/weight/material source.

## Distribution gates

A first-party standalone release requires all of the following.

### Runtime

- no third-party runtime implementation in the production output;
- no forbidden runtime imports;
- no remote runtime resources/network dependency;
- offline acceptance passes.

### Character/assets

- ORIGINAL provenance starts from the clean-room line;
- legacy/MakeHuman production coupling is zero;
- equipment/character/material/animation provenance is approved;
- release asset allowlist contains only approved first-party output.

### Behaviour/quality

- existing exercise generation and biomechanics remain valid;
- contacts/equipment relationships remain correct;
- visual/input parity gates required by migrations are complete;
- character deformation and whole-body movement tests pass.

### Documentation/evidence

- `FIRST_PARTY_COMPONENT_MANIFEST.json` reflects the final production state;
- `DOCUMENTATION_MANIFEST.json` has no unclassified docs;
- provenance and release audit evidence is current;
- `npm run audit:release` passes without weakened guards.

## Working principle

Use the existing product as a behavioural specification and engineering reference while replacing prohibited implementation/content. Preserve behaviour through measurable parity; do not copy third-party implementation or legacy creative data into the final product.
