This package exists so a **completely separate high-detail skin-mesh candidate** can be built
without disturbing anything already accepted. It contains no new geometry. Nothing in it was
rebuilt, re-exported or re-solved for this handoff — every file is a byte-verified copy.

---

## The one thing that is easiest to get wrong

**The accepted shoulder/arm correction is not inside a newer GLB.**

There is no "v9", no corrected character export, no newer mesh. The character binaries are still the
existing `CORNER_FINAL` bare and dressed assets, unchanged and byte-identical to the versions
accepted before the shoulder work began.

The corrected shoulder relationship lives in **the canonical rig and the exercise definition** —
that is, in code. It is applied at retarget time, every time the character is posed.

So:

> **Loading the GLB on its own reproduces the OLD, uncorrected forward shoulder.**
> The GLB must be used together with the corrected rig state from commit `eca99bb`.

This is not a packaging convenience; it is a property of how the engine works. An attempt was made
to push the correction into the asset and it was measured to be ineffective — see
[Why the asset cannot carry it](#why-the-asset-cannot-carry-it).

## The corrected rig state

### Clavicle rest angle — the correction

`rig-and-code/src/rig/humanoid.ts`, `clavicle_l` (the right side is generated by mirroring):

```ts
head: vec3(-0.02, 1.42, 0.012),
tail: vec3(-0.17, 1.44, -0.035),   // corrected — was vec3(-0.17, 1.44, 0)
```

| | Before | After |
|---|---|---|
| Clavicle tail | `(-0.17, 1.44, 0)` | **`(-0.17, 1.44, -0.035)`** |
| Posterior angle | 4.5° | **≈ 17.5°** |

A real clavicle angles back 15–20° from the sternoclavicular joint to the acromion. Running almost
straight out put the shoulder girdle — and the whole arm with it — in front of the ribcage.

### The arm chain follows it

So the chain stays connected and every arm bone still hangs vertical:

```ts
upperarm_l  head/tail  z = -0.035
forearm_l   head/tail  z = -0.035
hand_l      head/tail  z = -0.035
```

### The finger knuckles move too — do not miss this

The five `FINGER_SPECS` knuckles are **absolute world rest positions**, not offsets, so they carry
the same −0.035:

```ts
thumb  (-0.163, 0.852, -0.013)      index (-0.171, 0.789, -0.003)
middle (-0.172, 0.788, -0.024)      ring  (-0.171, 0.789, -0.045)
pinky  (-0.168, 0.792, -0.065)
```

Leaving them on the old centre line tilts the hand's **measured** axis by
`atan(0.035 / 0.09) = 21.3°`, because the palm axis is derived from the mean knuckle position rather
than from the hand bone's tail. That single omission caused 4 of 13 failures on the first attempt,
including all three movement certifications.

## The re-solved curl

`rig-and-code/src/exercises/definitions/bicepCurl.ts`:

| Setting | Before | After |
|---|---:|---:|
| Bottom elbow (`jointTargets` `forearm_{l,r}` axis `x` `start`) | 6° | **16°** |
| Bottom upper-arm flexion (`startPose` `upperarm_{l,r}.x`) | 4.55° | **3°** |
| Peak upper-arm flexion (`peakPose` `upperarm_{l,r}.x`) | 8.55° | **7°** |
| Peak elbow | 126° | 126° (unchanged) |
| Upper-arm abduction | `z: -3` / `+3` | unchanged |

The curl previously bought the hanging dumbbell's thigh clearance by tilting the humerus **forward**
4.55°. Pulling the arm root back carries the hand back, so that clearance had to be re-found — but
re-taking it forward would reinstate exactly what the correction removes. It now comes from the
**elbow** instead: bending it at the bottom lifts the plate off the leg without tilting the humerus
at all. A soft elbow at the bottom of a dumbbell curl is also what a lifter actually does.

Abduction was **re-tested, not inherited**, against the corrected chain: every abduction ≥ 0 still
breaks `upper_arm_clear_l/r`, so it remains unusable as a clearance lever.

Phases are unchanged: Bottom → Mid → Peak → Return over 5.5 s, loop closed, authored 4° late
upper-arm drift for the squeeze preserved.

## The 8 known failures — deliberately unresolved

Current suite: **290 passed, 8 failed, 1 skipped.**

| Test | Failure | Cause |
|---|---|---|
| `exercises > Push-Up` ×3 | 2 technique rules; 22 IK targets; `hand_l` contact 0.0056 > 0.005 | hands plant on the floor and the arm root moved 35 mm, so authored targets no longer reach |
| `body/ecorche` ×2 | biceps patch 94 < 100; 108 inverted triangles > 80 | écorché sculpt built around the old arm position |
| `body/shoulder` | 6.77 > 5.5 | procedural-body shoulder metric, authored against the old chain |
| `muscles` | `deltoid_anterior_l` 0.0022 > 0.001 outside the skin | muscle belly fitted to the old arm |
| `editor/review` | two-hand grip-socket gate false | barbell sockets authored against the old hand positions |

**These are known, accepted, non-curl regressions and must not be silently retuned as part of the
mesh work.** They are the measured cost of correcting a rig every character shares. Fixing them
means re-authoring the push-up's targets, the procedural body, the muscle bellies and the two-hand
equipment sockets — which `docs/MODEL_APPEARANCE_PHASE.md` explicitly reserves ("non-curl exercises
may be used only as regression checks… Do not improve, tune or redesign them").

If the mesh work changes this count in either direction, say so explicitly rather than absorbing it.
A drop from 8 is as important to report as a rise.

One test *was* updated as part of the shoulder change, because it belongs to it:
`src/animation/animation.test.ts > curls through the authored range` hard-coded `6` and `126`; it now
reads them from `bicepCurl.jointTargets`.

## Why the asset cannot carry it

Worth knowing before attempting to bake the correction into a new mesh.

Editing `DEF-upper_arm.{L,R}` in the GLB is surgical and does move the imported rest pose
(`upper_arm.L` local z −26.70 → −66.70 mm for a 40 mm shift, BIN chunk byte-identical, only two node
matrices changed). **It does not reach the posed character.** Measured Jacobian, 50 mm of rest-space
shift along each axis, against the posed arm root:

| Rest shift | Posed Δx | Posed Δy | Posed Δz |
|---|---:|---:|---:|
| +50 mm x | +40.10 | +0.89 | −2.58 |
| +50 mm y | +0.83 | +0.02 | −0.05 |
| +50 mm z | −13.24 | −0.30 | +0.85 |

Rank ≈ 1 — every rest direction produces posed motion along one lateral world axis. A rotation would
be rank 3. Only the *magnitude* of the clavicle→shoulder rest offset survives; its direction is
absorbed, because the posed arm root is placed from the **canonical clavicle's frame** at the
imported clavicle→shoulder distance (`applyRetarget`'s attachment branch in
`rig-and-code/src/retargeting/retarget.ts`). A 40 mm asset edit moved the posed shoulder **1.0 mm**.

The reproduction script is included as `harnesses/armroot.mjs` so this can be re-checked rather than
taken on trust.

## Hard constraints for the new mesh candidate

1. **Create the new mesh only as a separate candidate.** Give it a new filename. Do not overwrite,
   replace or "update in place" either `CORNER_FINAL` file.
2. **Production v8 and `CORNER_FINAL` files must remain untouched.**
   `public/characters/HomeGymPT_Male_BASELINE_v8.glb` and `..._v8_SHORTS.glb` are the promoted
   production pair; `CORNER_FINAL` bare/dressed are the accepted baseline. All four stay byte-identical.
3. **Do not change `src/character/bundled.ts` or any production asset reference.** That file decides
   which character the app registers as default; repointing it is promotion, and promotion is not
   authorised. A candidate is reviewed by importing it through the app's own GLB import.
4. **Do not merge or promote anything.**
5. **Do not silently retune the 8 known failures**, and do not "fix" them as a side effect.
6. **Preserve grip and contact behaviour**, including `scene.extras.homeGymPT` solved-grip metadata
   and the hand topology it was measured against.
7. **Use the GLB together with the corrected rig state**, never the GLB alone — see the top of this
   document.

### If the new mesh is a dressed variant

The dressing pipeline must carry, from the source body: node **rest-pose matrices** (all 160 joints),
**inverse bind matrices**, and **`scene.extras.homeGymPT`**. Omitting the node matrices is a real
defect that has occurred here before: every vertex-level check passed while the dressed default
posed like an older body, because glTF nodes in these assets use `matrix` and never TRS — comparing
`node.translation` / `node.rotation` gives a false pass. Verify with
`harnesses/dressed_equivalence.test.mts`, which asserts 0.0000 mm across all 10,839 posed vertices.

## Note on the Stage 1 muscle layer

`muscleDeformation.ts` is active in the current state and adds pose-driven corrective morph targets
to the arms at load time — it is code-side and bakes nothing into the asset. It is exactly 0 at
Bottom and Return, so it does not affect a static mesh comparison there, but it *will* change the
arm silhouette at Mid and Peak. If a new mesh is compared against renders, match the frame.

It can be taken to 0% in the editor's Correctives panel ("Arm muscle contraction") without touching
an asset.
