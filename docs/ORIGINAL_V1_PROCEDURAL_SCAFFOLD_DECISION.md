# ORIGINAL v1 procedural scaffold decision

## Decision

The historical procedural profile body introduced at commit:

`e6ef05b4312a1928cc6fbb71b92a94ceaff1cc62`

is approved as a **project-authored clean-room scaffold candidate** for ORIGINAL v1.

It predates the MakeHuman anatomical-reference commit:
`fe1700bde766454a841e5726158d97bb75186271`.

The historical profile body is generated from project source data in:
- `src/body/profiles.ts`
- `src/body/mesh.ts`

It is not a copy of the later imported/high-detail character and is not generated from MakeHuman files.

## Why this matters

ORIGINAL v1 does not have to begin as hand-modelled geometry from an empty cube.

A factory-blank Blender file may generate/import a mesh built **only from the pinned historical project-authored profile specification** and use that as the first scaffold.

This can save substantial modelling time while preserving a clean provenance boundary.

## Strict pin

Use the profile/body data as it existed at:

`e6ef05b4312a1928cc6fbb71b92a94ceaff1cc62`

Do not use current `src/body/profiles.ts` values as the provenance source without a separate audit.

Reason: later profile/body work occurred after MakeHuman and imported-character experiments entered the project. The historical pin avoids ambiguity.

## Allowed use

The pinned scaffold may provide:
- initial body proportions;
- cross-section layout;
- initial project-authored topology generated by the loft algorithm;
- initial project-authored two-bone blend concept;
- a starting neutral silhouette for subsequent original modelling.

It is a scaffold, not the finished asset.

## Required rework before ORIGINAL v1 acceptance

The scaffold still needs substantial original modelling for:
- shoulders/axilla;
- hands and thumb web;
- fingers/knuckles;
- face/head;
- pelvis/groin;
- knees;
- feet;
- deformation topology;
- clean clothing;
- canonical v4 binding and weights.

Do not merely rename the historical procedural mannequin and call it ORIGINAL v1.

## Forbidden inputs remain forbidden

Do not use:
- MakeHuman `anatomical*.ts` arrays;
- imported V5/V6/V7/V8/CORNER_FINAL assets;
- V9–V15 geometry;
- legacy skin weights/UVs;
- shrink-wrap/retopology against those surfaces;
- imported-source bone transforms.

## Provenance chain

The intended clean lineage becomes:

project-authored historical profile specification @ e6ef05b
→ clean scaffold generated in factory-blank Blender
→ ORIGINAL v1 topology/anatomy rebuild
→ canonical v4 ORIGINAL bind/weights
→ original clothing/materials
→ movement-envelope validation
→ final first-party production asset

## Engineering note

The historical `mesh.ts` implementation uses Three.js objects to build geometry. Three.js is third-party runtime code and is being removed from the distributable.

For the clean-room asset, reimplement the simple profile-loft generation in project-owned Blender/Python tooling or another first-party converter. Do not require Three.js in the final asset-generation path merely because the historical implementation used it.
